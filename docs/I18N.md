# 国际化与语言切换

本文记录 PaperHelper C 端的语言支持范围、语言切换链路、文案组织方式和新增语言的步骤。**改动语言相关代码前先读完第 3、4 节**，这两节里的约束一旦破坏，「登录页语言切换点了没反应」这个 bug 会立刻复现。

## 1. 支持的语言

| 代码 | 母语名 | 英文名 | 方向 | 来源 |
| --- | --- | --- | --- | --- |
| `zh` | 简体中文 | Simplified Chinese | LTR | 手写，默认语言，文案源 |
| `zh-Hant` | 繁體中文 | Traditional Chinese | LTR | 机翻 + 校对 |
| `en` | English | English | LTR | 手写 |
| `bo` | བོད་ཡིག | Tibetan | LTR | 机翻 |
| `ug` | ئۇيغۇرچە | Uyghur | **RTL** | 机翻 |
| `de` | Deutsch | German | LTR | 机翻 |
| `ar` | العربية | Arabic | **RTL** | 机翻 |
| `ko` | 한국어 | Korean | LTR | 机翻 |
| `ja` | 日本語 | Japanese | LTR | 机翻 |
| `fr` | Français | French | LTR | 机翻 |
| `vi` | Tiếng Việt | Vietnamese | LTR | 机翻 |
| `es` | Español | Spanish | LTR | 机翻 |
| `it` | Italiano | Italian | LTR | 机翻 |
| `fa` | فارسی | Persian | **RTL** | 机翻 |

`zh` 是默认语言（`DEFAULT_LOCALE`），也是文案源。`en` 是兼容项：需求单列出的语言里没有英文，但站点原本就有 `en`，线上已有用户把偏好设成 `en`、`/en/*` 老链接也在用，因此保留在列表末尾，**不要因为「需求没写」删掉它**。

## 2. 文件布局

```text
frontend/src/i18n/
├── locales.ts                 语言注册表（唯一事实来源）
├── locales/<code>/common.json 各语言文案
├── routing.ts                 next-intl 路由与 Cookie 配置
├── request.ts                 服务端取文案（含 Cookie 兜底与 zh 兜底合并）
├── switch-locale.ts           切换副作用（Cookie + 标记 + 整页跳转）
├── locale-preference.ts       与账号偏好（UserSettings.language）的双向同步
├── runtime.ts                 组件外代码用的运行时翻译器
└── RuntimeLocaleBridge.tsx    把当前语言与消息表登记给 runtime.ts
```

`locales.ts` 导出：`LOCALES`（顺序即切换器展示顺序）、`AppLocale`、`DEFAULT_LOCALE`、`LOCALE_COOKIE`（`NEXT_LOCALE`）、`RTL_LOCALES`、`LOCALE_META`（母语名 / 英文名 / 方向）、`isAppLocale()`、`localeDir()`、`matchLocale()`。切换器、设置页、根布局的 `<html lang/dir>`、浏览器语言协商都从这里取值，**组件里不要另写语言列表**。

`matchLocale()` 把浏览器/系统语言标签归一化到站点语言：`zh-TW` / `zh-HK` / `zh-MO` → `zh-Hant`，`ug-Arab-CN` → `ug`（按主语言标签匹配），不受支持的语言返回 `null`（落到默认语言）。

## 3. 切换链路（改这里要看仔细）

`applyLocale(locale, pathname)`（`switch-locale.ts`）一次做三件事：

1. 写 `NEXT_LOCALE` Cookie（`routing.ts` 里注册，一年有效）。next-intl 中间件据此记住语言，之后访问 `/` 也会落到这个语言。
2. 在 `localStorage` 写 `paperhelper.locale-chosen`，记录「用户亲自选过语言」。
3. **整页跳转** `window.location.assign()` 到同一路由的新语言地址。

第 3 步必须是整页跳转，不能改成 `router.push`：根布局 `frontend/src/app/layout.tsx` 位于 `app/[locale]/` **之上**，`<html lang>`、`<html dir>` 和 `NextIntlClientProvider` 都挂在它上面，而客户端软导航只重渲染 `[locale]` 以下的子树。用软导航，界面文案会停在旧语言——这正是「登录页语言切换点了没反应」的根因。

第 2 步的标记也不能省。next-intl 中间件每次请求都会按协商结果把 `NEXT_LOCALE` 写上，所以 **Cookie 有值 ≠ 用户选过**；`hasExplicitLocaleChoice()` 读的就是这个 localStorage 标记，用来区分「用户选的语言」和「系统协商出来的默认语言」。

切换入口：

- 登录页 / 全局顶栏：`frontend/src/components/ui/LanguageSwitcher.tsx`，下拉列出全部语言（母语名 + 英文名），当前项打勾；已登录时选完顺手把语言写回账号偏好，写失败只 `console.warn`，不阻断切换。
- 设置页与偏好设置：`frontend/src/components/settings/LanguagePicker.tsx`，写入 `UserSettings.language`。

**下拉菜单的层叠要求**：菜单自身是 `z-50`，但 `z-index` 只在自己所在的层叠上下文里有效，真正决定胜负的是「挂菜单的那个容器」和相邻兄弟的 `z-index`。登录页 `(auth)/layout.tsx` 里顶栏与内容行都是 `z-10` 的兄弟，内容行在 DOM 里靠后，于是菜单会被登录卡片压住、落到卡片范围内的选项点不着——顶栏因此提到 `z-30`（`frontend/src/test/auth-layout.test.tsx` 锁的就是「顶栏严格高于内容行」）。**给切换器换位置时先确认新容器的 `z-index` 打得过它的兄弟**，只把菜单本身的 `z-50` 往上加是没用的。

**面板滚动条**：14 种语言列不下，两个面板都得能滚（`overflow-y-auto` + `max-h`），但**不能露出滚动条**——面板本身有圆角和阴影，`globals.css` 里那条全局 `::-webkit-scrollbar`（6px、`--text-tertiary`）会贴着右边缘切进去，和圆角对不齐。两处面板都挂 `scrollbar-hidden`（定义在 `globals.css`）：`scrollbar-width` 管 Firefox、`-ms-overflow-style` 管旧 Edge、`::-webkit-scrollbar` 管 Chromium/Safari，**三条缺一不可，少一条就有浏览器露出来**；`frontend/src/test/language-panel-scrollbar.test.tsx` 同时锁住「面板有 `scrollbar-hidden` 且仍有 `overflow-y-auto`」和 CSS 里那三条声明。给面板加滚动条留白的 `pe-1` 之类也要一并去掉，否则滚动条没了，留白还在，内容会偏。

## 4. 语言与账号偏好

用户的偏好存在后端 `UserSettings.language`（默认 `zh`），走既有的 `GET/PUT /api/settings`，**后端不校验取值**，非法值在前端由 `isAppLocale()` 忽略。两条同步路径（`locale-preference.ts`）：

- 登录成功后 `settleLocaleAfterLogin(locale, pathname)`：这台设备上用户主动选过语言 → 把所选语言写进账号偏好；没选过（新设备）→ 读账号偏好，并把界面整页切到偏好语言。这样换设备登录看到的还是自己设定的语言，同时不会覆盖用户的显式选择。
- 登录页/顶栏/设置里切语言时，已登录就 `saveLocalePreference(locale)`。

## 5. 文案组织

- 源文件是 `frontend/src/i18n/locales/zh/common.json`（828 条叶子文案）。**每种语言必须与 zh 等键**，缺键时 `request.ts` 会合并 zh 兜底，用户看到的是中文而不是 key 名，因此缺键不会报错但会「漏翻」，交付前必须逐语言核对。
- 占位符写成 `{count}` / `{name}` 这类花括号形式，翻译时不许改名、不许丢。
- 组件内用 `useTranslations()`；`title` / `placeholder` / `aria-label` 同样要取文案，这些最容易漏。
- **组件外代码**（`lib/api/client.ts`、`lib/ai-provider.ts`、`lib/ai-chat-response.ts`、`lib/device.ts`、各 Zustand store、动态 import 的 `loading` 回调）用 `runtimeTranslator()`。消息表由根布局里的 `RuntimeLocaleBridge` 在**渲染期**登记（不是 `useEffect`，否则首屏之后立刻发起的请求取不到）。取文案要写在**调用的函数体内**，写成模块顶层常量会在语言切换后留下旧语言。
- 无语言前缀的路径（目前只有 `/callback`，被 `src/middleware.ts` 刻意绕开 intl 中间件）拿不到 locale 头，`request.ts` 里补了 Cookie 兜底。next-intl 自身不读 Cookie（`getRequestLocale` 只认中间件头），**那段兜底不能删**，删了 GitHub 回调页会永远停在简体中文。

## 6. RTL（`ar` / `fa` / `ug`）

两件事配合：

1. 根布局按 `localeDir(locale)` 设置 `<html dir="rtl">`。
2. 布局代码用 Tailwind 逻辑方向工具类：`ms-` / `me-` / `ps-` / `pe-` / `start-` / `end-` / `text-start` / `text-end` / `border-e` / `border-s`。**新写布局不要用 `ml-` / `mr-` / `pl-` / `pr-` / `left-` / `right-` / `text-left` / `text-right`**，否则这三种语言下元素会钉死在左边。

少数必须按物理方向摆放的元素（例如 PDF 阅读器内部与第三方组件）可以保留物理类，但要意识到它在 RTL 下不会镜像。

## 7. 新增一种语言

1. `locales.ts`：把语言代码加进 `LOCALES`，在 `LOCALE_META` 补母语名、英文名、方向（RTL 语言同时确认 `RTL_LOCALES` / `localeDir`）。
2. 复制 `locales/zh/common.json` 到 `locales/<code>/common.json`，逐条翻译，保持键结构与顺序。
3. 与 zh 比对键集合，确认无缺键、无多余键；抽查占位符。
4. 跑前端全量检查（`npx tsc --noEmit`、`npx vitest run`、`npm run lint`、`npm run build`），确认 `matchLocale` 的浏览器协商能落到新语言。
5. 手工看一眼该语言下的登录页、工作台、设置页，特别是长文案是否撑破按钮/侧栏（藏文、维吾尔文、德文最容易超长）。
6. 在 `README.md` / `PROJECT_STATUS.md` / 本文的语言表里补上。

## 8. 已知边界

- 除 `zh` / `en` 外，其余语言的文案来自批量机器翻译（经由外部代理，脚本不入库），**不保证术语一致性与文学性**；产品侧若要对外宣传多语言，建议对高频页面做一轮人工校对。
- 语言包只覆盖 UI 文案。论文元数据、GROBID 解析结果、用户内容、AI 模型输出不受语言设置影响。
- 后端返回的错误信息（`message` 字段）仍是中文，前端按错误码/兜底文案展示；新增接口若要参与国际化，应返回可被前端映射的错误码。
- `src/stores/chat-store.ts` 里的 AI 系统提示词**保持中文、不进语言包**：它显式要求模型「始终使用与用户提问相同的语言回答」，提示词本身用什么语言写不影响回答语言；翻成 13 种语言只会让翻译结果反过来影响模型行为，得不偿失。同文件里由提示词生成的内容（会话标题）也由模型按用户语言输出。
- 系统生成用户名（`lib/user-display.ts` 的「用户{id}」/「用户」）走 `runtimeTranslator("userDisplay")`，所以会跟着界面语言变；用户自己设过的昵称永远优先。
- 语言偏好不写 Cookie 之外的本地持久化；清空浏览器数据后，新设备会跟随账号偏好，未登录时跟随浏览器语言，都没有则用简体中文。
