# PaperReader 迭代计划

## 当前迭代：v0.1.11

分支：`feature/v0.1.11`

### 目标

重构 C 端右侧 AI 对话面板，使 Provider 配置、模型选择、创建对话和历史对话形成清晰的单一操作流程。

### 已完成

- 顶部 Provider 状态在未配置时显示警告图标和“未配置 Provider”。
- 点击警告或 composer 中的 Provider 操作，直接打开偏好设置的“AI 配置”页。
- 顶部“新对话”改为消息框加号图标按钮。
- 顶部增加历史对话下拉入口。
- 对话标题在首条消息后自动取首条消息摘要。
- 对话历史按浏览器用户的本地 Zustand 持久化保存。
- 模型选择器移入底部 composer 工具栏。
- 未配置 Provider 时模型选择器保持不可用，触发操作会提示先配置 Provider。
- 输入区域改为一体化 composer，模型选择、Provider 配置和发送按钮位于底部工具栏。
- 暂不加入语音输入，保留后续扩展空间。
- 更新 v0.1.11 版本信息和项目文档。

### 验收标准

- 未配置 Provider 时，页面不把 fallback 模型伪装成可用模型。
- 配置并激活 Provider 后，模型列表来自该 Provider；没有自定义模型时才使用内置兼容列表。
- 点击 Provider 配置入口能直接看到 AI 配置 Tab。
- 新建对话不会把已有消息混入新会话。
- 切换历史对话后，消息和模型能恢复。
- 刷新页面后，本地历史对话仍可见。
- Enter 发送，Shift+Enter 换行；发送中不能重复提交。
- 明亮/暗色主题下控件具有足够对比度。
- 构建、测试、重启和公网检查均通过。

## 后续计划

### v0.1.12（待确认）

- 评估将直接 Provider 对话同步到后端账户历史的必要性。
- 为历史对话增加删除、重命名和按 Provider 筛选。
- 为模型选择记忆每个 Provider 的最近选择。
- 评估输入框自动高度和长消息性能。

### 后续中版本（需明确授权）

- 语音识别输入：必须先定义浏览器权限、语音服务 Provider、隐私提示和失败回退。
- 多模态模型能力：需要区分“已粘贴图片”与 Provider 是否支持视觉输入。
- 服务端加密保存 Provider 配置和跨设备对话同步。

以上中版本事项不会在普通 patch 迭代中自动实施。
