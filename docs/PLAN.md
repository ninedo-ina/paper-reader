# PaperReader 迭代计划

## 当前迭代：v0.1.20

分支：`feature/v0.1.20`

迭代类型：功能需求。优化论文卡片操作区，并增加可选择是否物理删除原文件的论文删除流程。

### 本次目标与范围

- 调整论文卡片元数据行布局，为分类标签和三点菜单分别预留独立空间，避免点击区域和视觉重叠。
- 在原有收藏、标签、分享、下载操作后增加红色“删除”操作。
- 删除操作使用项目内二次确认弹窗，明确提示论文记录及关联数据不可恢复。
- 确认弹窗提供默认不勾选的“同时删除原文件”复选框；勾选后物理删除服务器文件，不勾选则保留服务器文件副本。
- 后端显式清理批注及评论、笔记、阅读记录、AI 会话及消息、论文版本、标签和全文解析 chunks。
- 列表 DTO 返回真实 `hasOriginalFile` 状态，只有服务器确有文件时才展示原文件复选框。

### 验收标准

- 窄侧栏与宽列表卡片中，分类标签和三点按钮始终保持间距，按钮可稳定点击。
- 三点菜单显示删除项，点击后不会立即删除，而是打开二次确认弹窗。
- 默认确认只删除 PaperReader 记录；勾选后确认同时删除原文件，界面文案明确说明服务器不再保留副本。
- 文件删除失败时接口返回错误，数据库删除事务回滚，前端保留卡片并显示错误。
- 用户不能删除其他用户的论文或文件；手工创建且没有文件的论文不显示原文件复选框。
- 自动化测试覆盖菜单入口、复选框默认值、两种删除方式、权限校验、文件失败和关联数据清理。
- 前端类型检查、测试、生产构建和后端 `clean test bootJar` 全部通过。

### 本次不包含

- 不提供服务器孤儿文件管理、回收站或删除后的恢复功能。
- 不修改 AI Provider、PDF 解析算法或论文编辑功能。
- 不修改后台管理项目 `/root/paperread-admin`。

## 历史迭代：v0.1.13-fix

分支：`feature/v0.1.13-fix`

### 目标

修复偏好设置中 AI Provider“测试连接”误报失败的问题，使测试请求与实际对话请求使用同一条 `/chat/completions` 流程。

### 已完成

- 已填写模型时直接测试实际使用的 `/chat/completions`，不再先依赖 `/models`。
- 未填写模型时才请求 `/models` 获取模型，并使用获取到的第一个模型测试 chat。
- 不再猜测 `gpt-4o-mini`，避免自定义 Provider 因模型不存在被误判为连接失败。
- 统一 Base URL 规范化、Authorization 请求头和错误脱敏逻辑，聊天发送路径复用同一套工具。
- 错误提示包含真实 chat HTTP 状态和 Provider 错误消息，但不会泄露 API Key。
- 更新 `0.1.13-fix` 版本信息和 favicon 缓存参数。

### 验收标准

- 已配置模型时测试按钮只发起 chat 请求，且请求模型等于配置模型。
- 未配置模型时能从常见 `/models` 响应格式提取模型，再测试 chat。
- `/models` 不可用时不会使用猜测模型，界面会明确提示填写模型。
- chat 接口失败时显示 chat 接口真实错误，而不是旧的 `/models` 错误。
- 浏览器请求带有 `v=0.1.13-fix-r1` 的 favicon 缓存参数。
- 首页左上角 Logo 与页面其他品牌元素未被本次修复影响。
- 构建、测试、重启和公网检查均通过。
