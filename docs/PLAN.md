# PaperReader 迭代计划

## 当前迭代：v0.1.18-fix

分支：`feature/v0.1.18-fix`

迭代类型：问题修复。修复 `v0.1.18` Provider 连接测试和对话请求在浏览器 CORS/错误 API 根路径下失败的问题。

### 本次目标与范围

- Provider Base URL 自动尝试标准 `/v1` API 根路径，并在成功后保存纠正后的地址。
- 浏览器直连因 CORS 或网络策略失败时，通过同源、JWT 保护的 Provider relay 完成模型发现和聊天请求。
- 保留上游 HTTP 状态和安全错误摘要，避免把 HTML 页面误认为模型响应。
- 不在代码、日志、提交、文档或截图中保存或输出 Provider API Key。

### 验收标准

- `https://lzhiyu.ccwu.cc/v1/models` 能发现模型，`gpt-oss-20b` 的 `/v1/chat/completions` 能返回正文。
- Base URL 填写 `https://lzhiyu.ccwu.cc/v1`、模型填写 `gpt-oss-20b` 时，连接测试和实际对话均可工作。
- 直连可用时不调用 relay；直连因 CORS 失败时，relay 能完成流式和非流式响应转发。
- relay 的 SSE 响应必须完整结束：包含 `[DONE]`、客户端正常关闭，且 Servlet 异步二次分发不会产生授权异常。
- 前后端测试、生产构建、PM2 重启和公网健康检查全部通过。

### v0.1.18 已完成范围

- 用户消息显示当前登录用户头像；助手保留 Bot 图标并显示昵称 `PR助手`。
- 每个本地历史会话独立保存 Provider 和模型；新对话继承上一个对话的选择，切回历史时恢复原配置。
- 首次成功回复后由当前会话的 Provider/模型生成标题，不直接复制用户问题；原样复述问题的标题不采纳。
- 历史列表显示创建时间、最后对话时间、Provider、模型和会话自己的回复中状态。
- 发送状态按会话 ID 管理；一个会话等待时，另一个未等待的会话仍可发送，异步回复不能串线。

### v0.1.18 已完成验收

- 前端类型检查、全部测试和生产构建通过；后端测试及 `bootJar` 通过。
- 新会话继承配置，历史会话互不覆盖 Provider/模型。
- 标题生成失败不影响正文成功回复。
- 版本分支推送后按 `feature -> dev -> main` 流程合并，生产 PM2 重启并完成公网验证。

### v0.1.18 未包含范围

- 服务端/跨设备历史同步、历史删除或手动重命名。
- 语音输入、工具调用和服务端托管 Provider 密钥。
- 后台管理项目 `/root/paperread-admin`。

## 历史迭代：v0.1.13-fix

分支：`feature/v0.1.13-fix`

### 目标

修复偏好设置中 AI Provider“测试连接”误报失败的问题，使测试请求与实际对话请求使用同一条 `/chat/completions` 流程。

### 已完成

- 已填写模型时直接测试实际使用的 `/chat/completions`，不再先依赖 `/models`。
- 未填写模型时才请求 `/models` 获取模型，并使用获取到的第一个模型测试 chat。
- 不再猜测 `gpt-4o-mini`，避免自定义 Provider 因模型不存在被误判为连接失败。
- 统一 Base URL 规范化、Authorization 请求头和错误脱敏逻辑，聊天发送路径复用同一套工具。
- 错误提示包含真实 chat HTTP 状态和 Provider 错误消息，但不会泄露 API Key。
- 更新 `0.1.13-fix` 版本信息和 favicon 缓存参数。

### 验收标准

- 已配置模型时测试按钮只发起 chat 请求，且请求模型等于配置模型。
- 未配置模型时能从常见 `/models` 响应格式提取模型，再测试 chat。
- `/models` 不可用时不会使用猜测模型，界面会明确提示填写模型。
- chat 接口失败时显示 chat 接口真实错误，而不是旧的 `/models` 错误。
- 浏览器请求带有 `v=0.1.13-fix-r1` 的 favicon 缓存参数。
- 首页左上角 Logo 与页面其他品牌元素未被本次修复影响。
- 构建、测试、重启和公网检查均通过。
